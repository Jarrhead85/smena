# Стандарты кода и Definition of Done

## 1. C#

- Nullable reference types включены.
- Использовать `async/await` сквозным образом; не использовать `.Result`, `.Wait()`, `async void` кроме допустимых event handlers с обработкой ошибок.
- Все длительные операции принимают `CancellationToken`.
- Время приходит через `IClock`; не вызывать `DateTime.Now` в Core.
- Публичные идентификаторы и код — на английском; UI-строки — в русских ресурсах.
- Не создавать универсальные `Repository<T>`, `ServiceManager`, `HelperHelper` и интерфейсы без второй реализации/необходимости изоляции.
- DTO внешнего API отделены от доменных моделей; `JsonSerializer` не маппит внешний ответ напрямую в сущности БД.
- Исключения используются для исключительных ситуаций; ожидаемые пользовательские ошибки представлены безопасным результатом/кодом.

## 2. MVVM и XAML

- ViewModel не ссылается на Android types, `HttpClient`, DbContext или файловые пути напрямую.
- Команды защищены от повторного выполнения и поддерживают отмену, если операция длительная.
- Не размещать бизнес-правила в code-behind. Code-behind допустим для платформенного поведения view.
- XAML использует семантические токены и ресурсы. Нет дублирования цветов/размеров.
- Коллекции виртуализируются. Не создавать 200 полноценных панелей вручную в `StackLayout`.
- Привязки проверяются на runtime binding errors.
- Для динамических/пустых/ошибочных состояний есть реальная разметка и accessibility.

## 3. EF Core и файлы

- Явные миграции, foreign keys и индексы.
- Короткие DbContext scopes; никакого глобального mutable singleton.
- Многошаговые доменные изменения атомарны.
- После коммита выполняется системная синхронизация; её ошибка сохраняется отдельно.
- Файловые операции проверяют, что путь остаётся в app-private каталоге. Не доверять внешнему имени файла.
- Большие изображения обрабатываются потоково; bitmap освобождаются.

## 4. HTTP

- `HttpClient` управляется фабрикой/долгоживущим клиентом; не создавать сокеты на каждый вызов через `new HttpClient` без контроля.
- Timeout, cancellation, ограниченный retry и безопасные ошибки обязательны.
- Логируется только sanitised metadata. Запрещено логировать headers/body целиком.
- TLS verification не переопределяется.
- Внешние константы endpoint и лимиты сверяются с документацией; нет выдуманных полей API.

## 5. Android

- Вся платформенная реализация находится в `Platforms/Android` и предоставляется через Core interface.
- PendingIntent Immutable, явные Intents, стабильные request codes.
- Receivers проверяют action, ID и текущее состояние БД.
- Разрешения проверяются перед операцией и при возврате на экран.
- Нет foreground service или wake lock ради обычного напоминания без отдельного обоснования.
- Приложение не выполняет сетевой вызов из alarm receiver.

## 6. Тесты

- Название описывает поведение: `ConfirmImport_WhenTimeMissing_ReturnsValidationError`.
- Каждый доменный инвариант имеет положительный и отрицательный тест.
- Время тестируется на границах и ночной смене.
- Повторная операция проверяется на идемпотентность.
- Mock HTTP ответы содержат только синтетические данные.
- Тест не должен обращаться к реальному GigaChat неявно; contract tests запускаются отдельно.

## 7. Git и зависимости

- Маленькие scoped commits; Conventional Commits рекомендуются, например `feat(shift): add manual assignments`.
- Не смешивать форматирование всего решения с функциональным изменением.
- Новая зависимость требует назначения, лицензии, размера/поддержки и отсутствия нежелательной телеметрии.
- Не добавлять preview packages.
- Не коммитить `.env`, ключи, БД, фото, keystores, bin/obj, device logs и session state агентов.

## 8. Документация

Изменение поведения обновляет соответствующий FR/UX/contract/test. Изменение архитектурного решения добавляет запись в `РЕШЕНИЯ.md`. Комментарии объясняют неочевидную причину, а не пересказывают код.

## 9. Definition of Done

Задача готова, если:

1. Критерии приёмки реализованы без заглушек.
2. Нет видимых неработающих действий.
3. Ошибки, офлайн и отмена обработаны там, где применимо.
4. Добавлены/обновлены тесты и они фактически запущены.
5. Android build успешен для затронутой конфигурации.
6. Для device-функции выполнен device test или явно зарегистрирован незакрытый gate.
7. Проведён аудит PII/секретов в новых логах и данных.
8. UI соответствует kit и проверен на доступность.
9. Документация и решения обновлены.
10. Отчёт честно перечисляет непроверенное и риски.
