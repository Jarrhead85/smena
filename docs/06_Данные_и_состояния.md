# Модель данных и конечные автоматы

## 1. Общие правила

- Внутренние ID — GUID.
- Абсолютные моменты хранятся в UTC (`DateTimeOffset`).
- Дополнительно сохраняются локальное wall-clock время и `TimeZoneId` смены, чтобы смена системного пояса не меняла назначение молча.
- Технические времена создания/изменения заполняются через `IClock`.
- БД содержит медицинские данные и шифруется. Логирование содержимого сущностей запрещено.
- Удаление смены каскадно удаляет назначения, reminders, import sessions и локальные фото после отмены системных событий.

## 2. Shift

| Поле | Тип | Правила |
|---|---|---|
| `Id` | Guid | PK |
| `StartLocal` | string/local DateTime | Обязательно, без seconds |
| `EndLocal` | string/local DateTime | Обязательно, больше StartLocal |
| `StartAtUtc` | DateTimeOffset | Вычислено по поясу |
| `EndAtUtc` | DateTimeOffset | Больше StartAtUtc |
| `TimeZoneId` | string | Например, IANA ID устройства |
| `Status` | enum | Active, Completed |
| `CreatedAtUtc` | DateTimeOffset | Неизменно |
| `UpdatedAtUtc` | DateTimeOffset | При каждом изменении |
| `CompletedAtUtc` | DateTimeOffset? | Только Completed |
| `HistoryExpiresAtUtc` | DateTimeOffset? | Null = до ручного удаления |
| `RowVersion` | long | Оптимистичная конкуренция |

Инварианты: максимум один Active; длительность >0 и ≤24 часов; Completed неизменна, кроме явного возврата в Active.

## 3. Patient

| Поле | Тип | Правила |
|---|---|---|
| `Id` | Guid | PK |
| `FullName` | string | 1–200 символов после trim |
| `CreatedAtUtc` | DateTimeOffset | Обязательно |
| `LastUsedAtUtc` | DateTimeOffset | Для предложения существующего пациента |

Пациенты не должны автоматически объединяться по ФИО: возможны однофамильцы. Поиск существующего — только подсказка при ручном выборе.

## 4. Assignment

| Поле | Тип | Правила |
|---|---|---|
| `Id` | Guid | PK |
| `ShiftId` | Guid | FK Shift, индекс |
| `PatientId` | Guid? | FK Patient, null только для черновика |
| `PatientName` | string? | Снимок на момент назначения; обязателен при Confirm |
| `Room` | string? | До 30 символов |
| `Bed` | string? | До 30 символов |
| `DueLocal` | string/local DateTime? | Время в поясе смены |
| `DueAtUtc` | DateTimeOffset? | Обязательно при Confirm |
| `Procedure` | string? | Обязательно при Confirm, до 500 символов |
| `Dosage` | string? | До 500 символов, без интерпретации |
| `Comment` | string? | До 2000 символов |
| `ReviewState` | enum | Draft, Confirmed |
| `ExecutionStatus` | enum | Pending, Done, Skipped |
| `NeedsReview` | bool | Подсказка ИИ/валидатора |
| `ReviewReason` | string? | Безопасный текст/код причины |
| `SourceImageId` | Guid? | FK SourceImage |
| `SourceExcerpt` | string? | Фрагмент источника, не доказательство точности |
| `StatusChangedAtUtc` | DateTimeOffset? | Для Done/Skipped |
| `CreatedAtUtc` | DateTimeOffset | Обязательно |
| `UpdatedAtUtc` | DateTimeOffset | Обязательно |
| `RowVersion` | long | Конкуренция |

Индексы: `(ShiftId, DueAtUtc)`, `(ShiftId, ExecutionStatus)`, `SourceImageId`. Уникальность пациента/процедуры/времени не устанавливать: повторные одинаковые назначения могут быть корректны.

### Переходы статуса

```text
Pending → Done
Pending → Skipped
Done → Pending
Skipped → Pending
```

Любой переход в Done/Skipped отменяет будущие reminders и заполняет `StatusChangedAtUtc`. Возврат в Pending очищает его и синхронизирует только будущие reminders. Изменение клинических полей Done/Skipped требует подтверждения и переводит в Pending.

`Overdue` не хранится: `ReviewState=Confirmed && ExecutionStatus=Pending && DueAtUtc < now`.

## 5. ImportSession

| Поле | Тип | Правила |
|---|---|---|
| `Id` | Guid | PK и идемпотентность импорта |
| `ShiftId` | Guid | FK Shift |
| `Status` | enum | Preparing, Processing, Review, Confirmed, Cancelled |
| `CreatedAtUtc` | DateTimeOffset | Обязательно |
| `UpdatedAtUtc` | DateTimeOffset | Обязательно |
| `RowVersion` | long | Защита от двойного Confirm |

Разрешённые переходы:

```text
Preparing → Processing → Review → Confirmed
Preparing → Cancelled
Processing → Cancelled
Review → Preparing       # повторная обработка/добавление страниц
Review → Cancelled
Processing → Review      # даже с частичными ошибками страниц
```

Повторный Confirm с тем же ID и RowVersion не создаёт новые записи. После Confirmed сессия неизменна.

## 6. SourceImage

| Поле | Тип | Правила |
|---|---|---|
| `Id` | Guid | PK |
| `ImportSessionId` | Guid | FK, индекс |
| `SortOrder` | int | Порядок страниц |
| `LocalPath` | string | Только app-private путь |
| `ProcessingState` | enum | Pending, Uploading, Recognizing, Ready, Failed, Cancelled |
| `SafeErrorCode` | enum/string? | Без тела ответа |
| `RemoteFileId` | string? | Не является секретом, но не логировать |
| `RemoteDeletePending` | bool | True до подтверждённого remote delete |
| `RetainLocal` | bool | Из настройки на момент импорта |
| `UnparsedLinesJson` | string? | Медицинские данные; только в защищённой БД |
| `CreatedAtUtc` | DateTimeOffset | Для cleanup |

Локальный файл удаляется после Confirm/Cancel, если `RetainLocal=false`. Remote delete выполняется после распознавания, Confirm или Cancel по возможности; pending-записи обрабатываются при следующей сетевой операции, не через постоянный фоновый опрос.

## 7. Reminder

| Поле | Тип | Правила |
|---|---|---|
| `Id` | Guid | PK |
| `AssignmentId` | Guid | FK, индекс |
| `Kind` | enum | Advance, Due |
| `ScheduledAtUtc` | DateTimeOffset | Абсолютное системное время |
| `AndroidRequestCode` | int | Уникальный сохранённый код PendingIntent |
| `ScheduleState` | enum | Planned, Scheduled, Failed, Cancelled, Delivered |
| `SafeErrorCode` | string? | Без медицинских данных |
| `UpdatedAtUtc` | DateTimeOffset | Обязательно |

Уникальность: `(AssignmentId, Kind)` для активной текущей версии. Если нужна история системных операций, добавлять `Generation`; MVP может перезаписывать запись, сохраняя request code.

Инвариант: записи Reminder создаются только для Confirmed + Pending. При Done/Skipped/Completed Shift/Delete все связанные системные alarms отменяются.

## 8. Настройки

### Несекретные, Preferences/защищённая БД

- выбранная модель;
- API scope;
- интервал предварительного напоминания;
- тема;
- срок истории;
- retain photos;
- private lock-screen notifications;
- признак показанного onboarding и версия согласия.

### Секретные, SecureStorage

- `gigachat.authorization_key`;
- `database.encryption_key`;
- optional file encryption key.

Access token, expiry и ответы модели не сохраняются в Preferences.

## 9. Вычисление времени

1. Пользователь/ИИ задаёт локальные дату/время в контексте смены.
2. Доменный сервис проверяет попадание в `[StartLocal; EndLocal]`.
3. `TimeZoneInfo` смены переводит local в UTC.
4. При ambiguous/invalid local time из-за перехода времени запись требует ручного подтверждения конкретного UTC; автоматический выбор запрещён.
5. Напоминания используют UTC; UI показывает local смены.
6. Изменение системного времени/пояса вызывает resync, но не переписывает `DueLocal` автоматически.

## 10. Валидация подтверждения

Confirm разрешён, если для каждого оставленного назначения:

- `PatientName`, `Procedure`, `DueLocal` непусты;
- время однозначно преобразуется и находится в смене;
- `ReviewState` пока Draft;
- пользователь обработал все unparsed lines;
- смена Active;
- сессия Review и версия совпадает.

`NeedsReview=true` не блокирует после ручного редактирования/подтверждения, но флаг может остаться как источник истории. Подтверждение пользователя всей операции обязательно независимо от флагов.

## 11. Миграции и очистка

- Каждое изменение схемы — EF migration + тест upgrade с предыдущей версии.
- Не удалять БД автоматически при ошибке миграции.
- Автоочистка выбирает Completed с истёкшим `HistoryExpiresAtUtc`, отменяет alarms, удаляет файлы и строки.
- Очистка не требует сети. Remote deletion pending может продолжаться отдельно без блокировки локального удаления.
- Операция «Удалить все данные» также отзывает ключ из SecureStorage; remote account и ранее отправленные данные этим не управляются, что явно указано в UI.
