# План реализации и декомпозиция

## 1. Принцип

Разработка идёт вертикальными срезами. Сначала работает ручной план без ИИ, затем надёжные напоминания, затем импорт. Каждый этап заканчивается сборкой и проверяемым пользовательским сценарием. Не реализовывать все экраны статичными макетами до появления Core.

## 2. Этап 0 — окружение и spikes

**T0.1. Зафиксировать toolchain.** .NET 10 SDK, MAUI workload, Android SDK/JDK, emulator, `global.json`, CI build.

**T0.2. Создать пустой Android MAUI.** Только `net10.0-android`, запуск Debug/Release на эмуляторе.

**T0.3. SQLCipher spike.** Создать БД, закрыть процесс, открыть с ключом, проверить файл не в открытом виде и миграцию.

**T0.4. Notification spike.** Два точных alarm, notification action, reboot, denied permission, Doze. Без этого не выбирать окончательную реализацию scheduler.

**T0.5. GigaChat spike.** На синтетическом изображении: OAuth → upload → chat → parse → delete. Проверить TLS и доступные vision-модели.

**T0.6. Image pipeline spike.** Camera/gallery, EXIF rotation, resize/compress, качество текста, память.

Результат: короткие ADR в `РЕШЕНИЯ.md`; не оставлять небезопасный spike-код в production ветке.

## 3. Этап 1 — ручной план смены

**T1.1. Core models/enums.** Shift, Patient, Assignment, статусы, `IClock`.

**T1.2. Время смены.** Ночные смены, TimeZoneInfo, валидация границ, unit-тесты.

**T1.3. Persistence.** DbContext, SQLCipher, миграции, repositories, индексы.

**T1.4. Use cases.** CreateShift, AddAssignment, EditAssignment, DeleteAssignment, ChangeStatus, CompleteShift.

**T1.5. Оболочка UI.** Нижняя навигация, темы, ресурсы, токены UI kit.

**T1.6. Активная смена.** Empty state, форма смены, лента, временные группы, прогресс.

**T1.7. Форма назначения.** Добавление/редактирование/удаление, ошибки, сохранение при back.

**T1.8. История.** Список и read-only детали.

**Приёмка:** AT-001…AT-005, AT-013…AT-015 в части ручного плана; офлайн и restart.

## 4. Этап 2 — напоминания

**T2.1. Reminder model.** Request codes, вычисление Advance/Due, unit-тесты границ.

**T2.2. Android channels/notifications.** Public/private content, deep link.

**T2.3. Scheduler.** Schedule/cancel/resync, отмена обоих старых alarms перед заменой, безопасные ошибки.

**T2.4. Receivers.** Alarm, Done action, boot, time/timezone, permission state, package replaced; атомарный Dispatching и Posted только после Notify.

**T2.5. Permission UX.** Контекстные объяснения, banner, отдельные переходы для приложения/канала/exact alarms, проверочное уведомление.

**T2.6. Device tests.** Вся матрица из документа напоминаний.

**Приёмка:** ни одно подтверждённое изменение БД не остаётся без видимого результата синхронизации; критические device-сценарии пройдены.

## 5. Этап 3 — импорт и GigaChat

**T3.1. ImportSession/SourceImage.** Состояния, восстановление черновика.

**T3.2. Camera/gallery UI.** Несколько страниц, rotate/reorder/delete, отмена.

**T3.3. Secure settings.** Key/scope/model, проверка без PII, удаление ключа.

**T3.4. Auth/API clients.** Token cache, timeout, retry, sanitization. Каждая попытка загрузки использует новый поток изображения с явным владельцем.

**T3.5. Image preprocessor.** Ориентация, размер, JPEG, memory limits.

**T3.6. Recognition contract.** Prompt, JSON Schema, DTO, parser, validation, mapper.

**T3.7. File lifecycle.** Remote ID, delete/pending, повторная очистка.

**T3.8. Progress/error UX.** По страницам, offline/retry/manual fallback.

**Приёмка:** успешный end-to-end импорт на тестовых данных; все contract/security tests.

## 6. Этап 4 — проверка и подтверждение

**T4.1. Review UI.** Фото, zoom, назначения, проблемы, сводка.

**T4.2. Редактирование черновика.** Все поля, добавить/удалить, unparsed lines.

**T4.3. Duplicate detection.** Только предупреждение, без автообъединения.

**T4.4. Confirm use case.** Транзакция, идемпотентность, scheduling, cleanup. Блокировка необработанных страниц, явное исключение страницы и отдельное подтверждение пустого результата.

**T4.5. Process death.** Восстановление Review и незавершённой загрузки.

**Приёмка:** AT-004…AT-010, AT-017; отсутствие scheduling до Confirm.

## 7. Этап 5 — hardening

**T5.1. Настройки retention/photo/privacy.** Автоочистка и полное удаление.

**T5.2. Accessibility.** TalkBack, 200% font, contrast, reduced motion.

**T5.3. Security.** FLAG_SECURE, backup rules, log audit, dependency scan.

**T5.4. Recognition benchmark.** Модель и ограничения задокументированы.

**T5.5. Холодный запуск и производительность.** 200 назначений, память фото.

**T5.6. Release candidate.** Signed build вне репозитория, полный чек-лист, известные ограничения.

## 8. Зависимости

```text
T0 → T1 Core/DB → T2 Notifications
T0 GigaChat/Image spikes ─┐
T1 Shift/Core ────────────┴→ T3 Import → T4 Review → T5 Hardening
T2 Scheduler ────────────────────────────────→ T4 Confirm → T5
```

UI kit и ресурсы создаются вместе с первым реальным экраном, а не отдельным декоративным проектом.

## 9. Правило задач для агентов

Одна задача должна иметь один узкий результат и проверку. Не объединять, например, GigaChat OAuth, UI настроек и импорт фото в один безразмерный шаг. После каждого этапа обновить статус задач и фактические результаты. При отклонении от плана сначала объяснить зависимость и риск.

## 10. Фактический статус на 11.11.2026

Создан Android-only .NET MAUI-проект с Core/Infrastructure/App. Реализованы ручной план и история, SQLCipher и миграция, Review и подтверждение импорта, GigaChat file/chat lifecycle, камера/галерея, локальные AlarmManager-напоминания, receivers, настройки retention/приватности и системная блокировка. Пользовательские строки вынесены в ресурсы.

Завершена реализация P0 PR-01…PR-05: блокировка неполного импорта и явное исключение страниц, новый поток изображения на каждую попытку, отмена старых системных alarms, атомарные состояния Dispatching/Posted и отдельная диагностика разрешений уведомлений, канала и exact alarms.

Дополнительно реализован текущий пакет v2:

- PR-20 — рабочее завершение смены с подтверждением при ожидающих назначениях и исправленные привязки команд;
- PR-05A — обновление фактических разрешений при возврате на видимый экран настроек;
- PR-04A/PR-21 — состояние RecoveryPending, 15-минутное окно восстановления и отбор напоминаний без сброса терминальных состояний при обычной синхронизации;
- PR-07A/07B — ручные черновики на каждой выбранной странице и корректное представление Excluded;
- PR-06 — защита Review от позднего завершения устаревшей загрузки страницы.

Проверка на хосте: 17/17 Core-тестов и 42/42 Infrastructure-тестов пройдены, Android Release build успешен, 0 ошибок и 44 предупреждения. A/B-сценарий PR-06 на фактическом `ReviewViewModel` подтвердил, что устаревшая загрузка не перезаписывает более новую страницу и ручной черновик.

На MTN-NX1 (Android 16, API 36) Release APK установлен с сохранением данных. Подтверждены запуск существующей БД, завершение пустой и непустой смены, отображение завершённых смен в истории, обновление канала уведомлений при Back и exact alarms при возврате через кнопку приложения. Разрешения после проверки включены. Подробности и ограничения зафиксированы в `docs/10_Тестирование_и_приёмка.md`, раздел 14.

Это не завершение всего плана v2 и не готовность к production. Не закрыты: реальная доставка и отмена напоминаний, reboot/Doze/process death, серия 20/20, полный device-сценарий Excluded, camera/gallery, API 26, AppLock, TalkBack и шрифт 200%, security device-чек-лист, реальный GigaChat contract и benchmark качества. Следующие пакеты после PR-07C также не входили в текущий цикл. Подписанный APK является результатом локальной сборки, не production release с утверждённым ключом и сопровождением.
