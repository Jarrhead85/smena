# Безопасность, приватность и жизненный цикл данных

## 1. Граница прототипа

Независимый прототип разрабатывается и тестируется на синтетических/обезличенных данных. До реального использования необходимо согласование с ответственными за информационную безопасность, защиту персональных данных и медицинскую эксплуатацию. Этот документ — инженерный минимум, а не юридическое заключение.

Приложение не является источником назначений. Оригинальный лист и действующие процессы организации сохраняют приоритет. Нельзя использовать дисклеймер как замену исправлению небезопасного поведения.

## 2. Классы данных

| Класс | Примеры | Основные правила |
|---|---|---|
| Медицинские/персональные | ФИО, палата, процедура, доза, комментарий, фото | Шифрование, минимизация, никогда не логировать |
| Секреты | Authorization Key, access token, ключ БД | SecureStorage/память, никогда не выводить |
| Технические | ID, remote file ID, request code, время запроса | Не публиковать; хранить только при необходимости |
| Несекретные настройки | Тема, интервал, модель, scope | Без медицинских данных |
| Диагностические | Категория ошибки, duration, version | Без тел запросов, путей с именами и PII |

## 3. Модель угроз MVP

- Потеря или временный доступ к разблокированному телефону.
- Чтение публичных уведомлений на заблокированном экране.
- Доступ к резервным копиям или app files.
- Компрометация Authorization Key.
- Перехват/подмена TLS при неправильном доверии сертификатам.
- Утечка через логи, crash reports, скриншоты, тесты и Intent extras.
- Оставленные удалённые файлы после ошибки или отмены.
- Ошибочное доверие к выдуманному результату модели.
- Вредоносный проектный агент, добавляющий стороннюю телеметрию или отключающий TLS.

Меры ниже обязательны даже при локальном хранении.

## 4. Хранение секретов

- Authorization Key вводится вручную и сохраняется через .NET MAUI `SecureStorage`.
- Ключ БД — случайный криптостойкий массив, хранится через SecureStorage/Android Keystore-backed механизм.
- Access token и expiry — только в памяти процесса.
- Ключ не отображается целиком после сохранения, не копируется автоматически и не включается в экспорт настроек.
- Удаление ключа требует подтверждения и не удаляет локальный план.
- При невозможности прочитать ключ БД приложение не сбрасывает базу молча.

## 5. Шифрование и резервные копии

- SQLite шифруется через SQLCipher; выбранная реализация проверяется spike и device test.
- Фото находятся только в app-private storage. При включённом сохранении содержимое шифруется; хранение открытого JPEG в долговременном каталоге не допускается.
- Cloud backup медицинской БД, фото и секретов отключён в Android backup rules.
- Данные не копируются в публичную галерею, Downloads, общий clipboard или внешние viewer.
- Экраны с медицинскими данными защищаются от скриншотов и превью в recents через `FLAG_SECURE`; device test обязателен.
- Автозаполнение и персонализированное обучение клавиатуры для медицинских полей отключаются, где поддерживается платформой.

## 6. Передача в GigaChat

- Отправка происходит только после действия «Распознать» и показанного уведомления о внешней передаче.
- Передаётся только выбранная страница и минимальный контекст смены.
- TLS verification всегда включена. Запрещены accept-all certificates, hostname bypass и `verify_ssl_certs=False`.
- Не доверять дополнительным пользовательским CA специально ради обхода ошибки. Необходимая цепочка НУЦ настраивается по официальной документации и политике устройства.
- Remote file удаляется через API после обработки; ошибка удаления сохраняется как pending.
- Приложение не заявляет об удалении всех копий у провайдера. До реального пилота проверяются условия обработки и хранения провайдером.

## 7. Логи и диагностика

Разрешено: версия приложения, операция, безопасная категория, HTTP status, duration, случайный correlation ID.

Запрещено: Authorization, cookies, access token, тела HTTP, JSON модели, ФИО, фото, base64, локальные пути с пользовательскими именами, полные исключения с request/response.

- Использовать централизованный санитайзер, но не полагаться только на него: сначала не записывать чувствительные значения.
- В Release отключить verbose HTTP logging.
- Не подключать внешнюю аналитику, рекламу, crash reporting и performance SDK в MVP.
- При локальном bug report данные собираются только по явному действию и показываются перед отправкой; медицинские данные не включаются.

## 8. Блокировка приложения

Для MVP предусмотреть настройку блокировки биометрией/кодом устройства при открытии и после ухода в фон. Если платформенная реализация не проходит надёжность и доступность, функция не выдаётся за готовую.

Перед реальным пилотом блокировка и политика устройства являются обязательным release gate. Разблокировка не должна требоваться для базового системного alarm receiver, но просмотр данных требует открыть защищённое приложение.

## 9. Уведомления и экран блокировки

По умолчанию публичная версия содержит только «Есть назначение» без ФИО и процедуры. Пользователь может явно разрешить подробный текст. Настройка объясняет риск видимости другим людям. Проверить поведение на контрольных Android-устройствах: одни только `VISIBILITY_PRIVATE` без корректной public version недостаточно.

## 10. Жизненный цикл фото

```text
Capture → app-private temp → preprocessing → upload → review
       → Confirm/Cancel → local delete (default)
       → Retain enabled → encrypted private storage до удаления истории
```

При старте очищаются orphaned temp files старше текущей незавершённой сессии. Нельзя удалять фото, пока пользователь проверяет черновик или выбрал сохранение. Ошибка удаления локального файла безопасно фиксируется и повторяется.

## 11. Удаление данных

- Завершение смены не удаляет записи.
- История удаляется по выбранному сроку или вручную.
- «Удалить все данные» отменяет alarms, удаляет БД/фото/настройки/Authorization Key и очищает recents по возможности.
- Remote deletion pending обрабатывается по возможности, но локальное удаление не блокируется отсутствием сети.
- UI прямо сообщает, что операция не управляет аккаунтом GigaChat и уже обработанными провайдером данными.

## 12. Безопасная разработка

- Только вымышленные пациенты: например, «Тестовый Пациент 001». Не копировать реальные листы в issue или prompt агента.
- Секреты сканируются в CI; `.gitignore` исключает локальные ключи, БД, фото, keystore и diagnostic output.
- Зависимости проверяются на происхождение, лицензию и уязвимости. Новые SDK требуют обоснования.
- Release signing key не хранится в репозитории.
- Код агентов и навыков рассматривается как конфигурация с полномочиями; не добавлять команды exfiltration, небезопасные hooks и загрузку удалённых prompt-файлов.

## 13. Обязательные security-тесты

1. БД и сохранённые фото недоступны как открытый текст в app files.
2. Backup rules не включают медицинские данные и секреты.
3. Logcat не содержит PII/секретов при успехе, ошибке, retry и отмене.
4. Notification public version и Intent extras не содержат PII.
5. Recents и screenshots блокируются на чувствительных экранах.
6. Недействительный сертификат приводит к ошибке, а не к принятию соединения.
7. Удаление/замена ключа не раскрывает старое значение.
8. Confirm невозможен без пользователя и критических полей.
9. Remote delete вызывается при успехе, ошибке распознавания и отмене; pending переживает перезапуск.
10. Полное удаление очищает локальные данные и отменяет alarms.
