# UI kit «Смена»

## 1. Дизайн-направление

Спокойный рабочий инструмент с нативным Android-характером. Визуальная иерархия строится на типографике, времени, отступах и разделителях, а не на обилии карточек. Никаких градиентов, стеклянных панелей, декоративных ИИ-звёзд, эмодзи, иллюстрированных пустых состояний и вложенных контейнеров.

Характерная деталь: крупное табличное время в каждом назначении. Оно выравнивается по единой левой колонке и образует визуальный ритм расписания.

## 3. Типографика

Использовать системный шрифт Android без скачиваемых шрифтов. Это уменьшает вес, сохраняет знакомость и поддерживает системные настройки.

| Стиль | Размер / межстрочный интервал | Начертание | Применение |
|---|---|---|---|
| `Text.ScreenTitle` | 28/36 sp | Semibold | Название экрана |
| `Text.SectionTitle` | 20/28 sp | Semibold | Временная группа |
| `Text.Body` | 17/26 sp | Regular | Основной текст |
| `Text.BodyStrong` | 17/24 sp | Semibold | Процедура, ключевое значение |
| `Text.Secondary` | 15/22 sp | Regular | Дополнительные сведения |
| `Text.Caption` | 13/18 sp | Regular | Метки, источник |
| `Text.Button` | 17/22 sp | Semibold | Кнопки |
| `Text.ScheduleTime` | 24/28 sp | Semibold | Время процедуры |

Не использовать All Caps, декоративный курсив и слишком тонкие начертания. Длинные ФИО и процедуры переносятся; критическое время не сокращается многоточием.

Учитывать system bars и safe area. Нижняя закреплённая кнопка имеет отступ от системной навигации. Горизонтальная прокрутка основного экрана запрещена; страницы фото — исключение при масштабировании.

## 5. Компоненты

### `PrimaryButton`

Текст обязателен. Высота ≥52 dp, Primary/OnPrimary. Состояния: default, pressed, disabled, loading. Loading сохраняет ширину, показывает индикатор и текст операции; повторное нажатие блокируется. На экране одна основная кнопка.

### `SecondaryButton`

Прозрачный/ Surface фон, граница Outline, текст Primary. Не использовать рядом более двух вторичных действий; остальные переносить в меню.

### `DangerButton`

Используется только для удаления и необратимых действий. Не является основным действием формы. Требует подтверждения с названием объекта.

### `TextField`

Видимая метка над полем, не placeholder вместо метки. Высота ≥52 dp. Ошибка располагается под полем и связывается с ним для accessibility. Секретное поле имеет действие показать/скрыть и не копируется в лог.

### `ScheduleRow`

Состав: фиксированная колонка времени, основная информация, статус, chevron. Быстрое «Выполнено» может быть отдельной кнопкой под основным содержимым, но не сливается с нажатием всей строки. Вся строка открывает детали.

Состояния: Pending, Done, Skipped, Overdue, NeedsReview, Disabled. Done — значок и текст «Выполнено»; Skipped — «Пропущено»; Overdue — «Просрочено на N мин».

### `StatusBanner`

Текст + иконка + одно действие. Используется для отсутствия сети, разрешений и ошибки синхронизации напоминаний. Не исчезает автоматически, пока проблема сохраняется.

### `BottomNavigation`

Три текстовых пункта со стандартными иконками. Активность обозначается цветом, весом и accessibility-состоянием. Не добавлять плавающую кнопку поверх навигации.

### `ConfirmationDialog`

Заголовок формулирует результат: «Удалить назначение?». Текст называет последствия. Кнопки: «Отмена» и конкретное действие. Не использовать «Да/Нет».

### `PhotoViewer`

Полноэкранный просмотр с масштабированием, поворотом, номером страницы и кнопкой закрытия. Не передавать изображение внешним viewer-приложениям.

### `EmptyState`

Один короткий заголовок, одно пояснение и одно основное действие. Без стоковых иллюстраций.

### `Skeleton/Progress`

Для локальной загрузки — статичные placeholder-строки или spinner. Для сетевого импорта — номер страницы и понятная операция. Не имитировать проценты, если фактический прогресс неизвестен.

## 6. Иконки

Использовать один согласованный набор Material Symbols или встроенные платформенные ресурсы. Размер 24 dp, цвет наследуется от текста. Любая неочевидная иконка имеет текстовую метку. Запрещены эмодзи вместо иконок и самостоятельно нарисованные несогласованные SVG.

Минимальный набор: календарь/смена, история, настройки, камера, галерея, плюс, назад, закрыть, повернуть, удалить, выполнено, пропущено, предупреждение, ошибка, редактировать, уведомление.

## 7. Движение и обратная связь

- Нажатие: 80–120 мс; переход экрана: 180–220 мс.
- Анимируются только opacity и transform; никаких бесконечных декоративных анимаций.
- Успешное выполнение: обновление строки и короткая тактильная отдача, если разрешено системой.
- Ошибка: не использовать тряску как единственную обратную связь.
- Snackbar подходит для обратимых/неблокирующих сообщений. Потеря напоминаний требует постоянного StatusBanner.

## 8. Реализация в .NET MAUI

- Токены разместить в `Resources/Styles/Colors.xaml` и `Styles.xaml`; светлые/тёмные значения через `AppThemeBinding` или theme dictionaries.
- Не вписывать HEX и размеры повторно в каждую страницу.
- Общие компоненты создавать только после двух реальных повторов; не строить чрезмерную библиотеку заранее.
- Использовать `CollectionView` для списков, `Grid`/`FlexLayout` для раскладки, семантические свойства для TalkBack.
- Не отключать автоматическое масштабирование шрифта. Проверять 200% на 360 dp ширине.
- Стили pressed/disabled/loading обязательны; отсутствие состояния — дефект.

## 9. Запрещённые решения

- Фиолетово-синие градиенты и светящиеся акценты.
- Центрированный marketing hero внутри рабочего приложения.
- Несколько одинаковых карточек с декоративными иконками на каждом экране.
- Настройка/статистика ради заполнения пустого места.
- Неподписанные иконки для ключевых действий.
- Автоматически исчезающие критические сообщения.
- Случайные цвета пациентов или процедур.
- Статус только красным/зелёным.
- Пользовательский текст мелким шрифтом ради помещения на одном экране.

## 10. UI-чек-лист

Перед приёмкой экрана проверить: 360 dp и 412 dp; светлую/тёмную тему; шрифт 100% и 200%; TalkBack; длинные ФИО/процедуру; пустое состояние; ошибку; офлайн; отказ разрешения; клавиатуру; safe area; все состояния кнопок; отсутствие горизонтального overflow; реальную работу каждого видимого действия.
