# AGENTS.md — постоянные правила проекта «Смена»

## Контекст

Разрабатывается Android-приложение на C# и .NET MAUI для одной медсестры на одном устройстве. Приложение импортирует назначения с фотографий через GigaChat, обязательно показывает результат для проверки, хранит план локально и напоминает о процедурах без интернета.

## Обязательно прочитать перед работой

1. `docs/01_Продуктовые_требования.md` — цель и границы.
2. `docs/02_Функциональное_ТЗ.md` — нормативные функциональные требования.
3. Документ своей предметной области из `docs/00_Карта_документов.md`.
4. `РЕШЕНИЯ.md` — если задача меняет архитектуру или принятые допущения.

## Несогласованность документов

Функциональное ТЗ и принятые решения имеют приоритет над примерами. При противоречии не выбирать вариант молча: указать конфликт, предложить минимальное согласованное исправление документов и только затем продолжить. Не расширять объём MVP без явного запроса пользователя.

## Неприкосновенные правила безопасности

- Результат ИИ является черновиком. Подтверждение всего импорта пользователем обязательно.
- Не создавать события и напоминания из неподтверждённых черновиков.
- Не выдумывать значения. Нечитаемое значение = `null` + причина проверки.
- Не давать медицинских рекомендаций, не рассчитывать дозы, не исправлять назначения по смыслу.
- Не логировать медицинские данные, содержимое изображений, Authorization Key, access token или заголовки авторизации.
- Не отключать проверку сертификатов и не добавлять `verify_ssl_certs=False` или аналоги.
- Использовать только синтетические данные в коде, тестах, скриншотах и примерах.
- Не добавлять аналитику, crash-reporting или внешние SDK, передающие данные, без отдельного решения.

## Инженерные правила

- Целевая платформа MVP: `net10.0-android`; стабильный .NET 10 LTS, без preview-компонентов.
- MVVM, `CommunityToolkit.Mvvm`, зависимость через интерфейсы, платформенный Android-код изолирован.
- Core не зависит от MAUI, Android, HTTP и SQLite.
- Все пользовательские строки — в ресурсах; русский язык первичен.
- Даты хранить в UTC вместе с локальным временем и часовым поясом смены. Не использовать неуказанный `DateTime.Now` в доменной логике; внедрить часы.
- Любое изменение назначения атомарно обновляет БД и затем синхронизирует напоминания; ошибка планирования видима пользователю.
- Не использовать фоновые опросы GigaChat. Сетевая активность возникает только по явному действию импорта или проверки настроек.
- Предпочитать небольшие проверяемые изменения. Не переписывать соседние функции ради стилистики.

## UX-правила

- Простой нативный Android-интерфейс, без градиентов, декоративных ИИ-элементов, эмодзи-иконок и вложенных карточек.
- Основной сценарий начинается с понятного действия, а не с чата.
- Крупные цели нажатия, системное масштабирование шрифта, TalkBack, контраст AA.
- Статус никогда не передаётся только цветом.
- Пустые, загрузочные, ошибочные, офлайн- и запрещённые разрешениями состояния являются частью каждой функции.
- Не оставлять видимых неработающих кнопок.

## Проверка и завершение

- Для каждой задачи определить критерии приёмки до реализации.
- Запустить релевантные unit/integration-тесты и сборку Android.
- Для напоминаний, камеры и разрешений недостаточно unit-тестов: требуется реальное устройство или эмулятор с задокументированным сценарием.
- Не утверждать, что проверка выполнена, если команда или сценарий фактически не запускались.
- В отчёте перечислить: изменения, выполненные проверки, невыполненные проверки, оставшиеся риски.
- Обновить документацию при изменении поведения, контракта или структуры.

## Секреты

Не записывать реальные ключи в `appsettings`, Markdown, переменные репозитория или код. В приложении Authorization Key вводится пользователем и сохраняется только через защищённое хранилище платформы. Access token живёт в памяти и не сохраняется постоянно.
