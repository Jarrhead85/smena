# Clinical UI review

## Порядок ревью

1. Прочитай `docs/03_UX_и_экраны.md` и `docs/04_UI_kit.md`.
2. Определи пользовательскую задачу и критическое действие экрана.
3. Проверь реальные состояния и взаимодействия, не только статичный XAML.
4. Проверь 360/412 dp, светлую/тёмную тему, font 100/150/200%, длинные строки, TalkBack и reduced motion.
5. Зафиксируй findings с серьёзностью, файлом, состоянием и способом воспроизведения.

## Приоритеты

### Блокеры

- Невозможно выполнить основной сценарий или понять ошибку.
- Видимая кнопка ничего не делает.
- Время/критическая кнопка обрезана при 200% font.
- Статус передан только цветом.
- Критическое предупреждение исчезает автоматически.
- Фото/медицинские данные раскрываются внешним viewer или публичным notification.
- Пользователь может случайно Confirm без проверки блокирующих ошибок.

### Основные требования

- 48 dp targets; основной текст 17 sp; вторичный ≥15 sp.
- Контраст AA, текстовые labels, safe area, keyboard и back behavior.
- Одна primary CTA; пропуск/удаление защищены от случайного нажатия.
- Empty/loading/error/offline/permission states реализованы.
- Лента сортируется по времени и не перегружена вложенными карточками.

### Антишаблонный дизайн

Удали/предложи замену: градиенты, ИИ-звёзды, эмодзи-иконки, marketing hero, декоративные иллюстрации пустых состояний, множество одинаковых панелей, случайные цвета, модные шрифты и анимации ради украшения. Системный Android font и крупное табличное время являются осознанным направлением.

## Формат результата

1. Вывод: пройдено / требуются изменения.
2. Findings: blocker/high/medium/low, доказательство и конкретное исправление.
3. Проверенные матрицы и фактические скриншоты/device runs.
4. Непроверенное — отдельно; не заменяй его общим «UX хороший».
