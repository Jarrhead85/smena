# «Смена» — комплект для Kimi Code

## Назначение

Это исходный комплект для разработки Android-приложения «Смена»: личного планировщика медсестры с распознаванием листов назначений через GigaChat, обязательной ручной проверкой и локальными напоминаниями.

Рабочее название идентификатора приложения: `NurseShift`. Название «Смена» можно изменить до публикации без влияния на архитектуру.

## Как установить комплект

1. Создайте пустой репозиторий будущего приложения.
2. Скопируйте в его корень **всё содержимое** этой папки, включая скрытый каталог `.kimi-code`.
3. Не переименовывайте `AGENTS.md`, `SKILL.md`, файлы агентов и каталоги `.kimi-code`.
4. Запустите Kimi Code из корня репозитория или перезапустите уже открытую сессию, чтобы агенты и навыки были обнаружены.
5. Откройте `docs/00_Карта_документов.md` и `prompts/01_Первичная_настройка.md`.
6. Передайте Kimi Code первичный промпт. Не просите реализовать весь проект одним изменением.

Опционально можно запустить главного координатора:

```bash
kimi --agent shift-coordinator
```

Навыки доступны автоматически и вручную, например:

```text
/skill:nurse-shift-domain
/skill:maui-android-implementation
/skill:gigachat-recognition
/skill:clinical-ui-review
/skill:shift-release-verification
```

## Что входит

- `AGENTS.md` — постоянные правила для любого агента в репозитории.
- `docs/` — продуктовое и техническое ТЗ, UX/UI, архитектура, безопасность, тестирование и план работ.
- `contracts/` — машинночитаемый контракт результата распознавания и безопасные примеры.
- `.kimi-code/agents/` — специализированные агенты Kimi Code.
- `.kimi-code/skills/` — проектные навыки в открытом формате Agent Skills.
- `prompts/` — готовые задания для последовательной разработки.
- `РЕШЕНИЯ.md` — принятые решения, предположения и правила их изменения.

## Главные ограничения

- Нельзя создавать напоминания из результата ИИ до явного подтверждения пользователем.
- Нельзя выдумывать непрочитанные поля или выполнять клинические выводы.
- Нельзя отключать проверку TLS ради успешного запроса.
- Нельзя помещать ФИО, фото листов, ключи или токены в логи, тесты, скриншоты и репозиторий.
- План, редактирование, статусы и напоминания работают без интернета.
- Пропущенная процедура не выставляется автоматически только из-за истечения времени.
- Любое видимое действие интерфейса должно работать; заглушки не считаются готовой функцией.

## Рекомендуемый порядок разработки

1. Проверка инструментов и технические прототипы.
2. Ручной ввод, локальная база и лента активной смены.
3. Напоминания, перезагрузка устройства и обработка разрешений.
4. Камера, галерея и импорт нескольких листов.
5. GigaChat, строгая проверка ответа и удалённое удаление файлов.
6. Экран проверки, подтверждение и планирование напоминаний.
7. История, настройки, доступность, защита и полное тестирование.

## Важное ограничение использования

Комплект описывает независимый прототип. Перед использованием с реальными пациентами необходимо отдельно согласовать обработку медицинских данных, передачу изображений внешнему сервису, политику хранения, защиту устройства и процедуру эксплуатации с ответственными специалистами организации. Приложение не заменяет лист назначений и не принимает клинических решений.
