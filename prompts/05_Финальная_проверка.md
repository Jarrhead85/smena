# Промпт: финальная проверка

Используй `shift-release-verification`, затем при необходимости `clinical-ui-review`.

Проведи независимую проверку, а не пересказ кода:

1. Проследи каждый FR до реализации и теста; составь список пробелов.
2. Запусти unit/integration/contract tests и Android Release build.
3. Проверь AT-001…AT-018 и все доступные device/security сценарии.
4. Проверить отсутствие scheduling до Confirm, автопропуска, PII в logs/Intent/public notification, TLS bypass и секретов в репозитории.
5. Проверь UI на 360/412 dp, темы, font 200%, TalkBack, длинные строки, ошибки, offline и все видимые действия.
6. Проверь backup rules, local/remote deletion, process death и полное удаление.
7. Сообщи findings по серьёзности с файлами и воспроизведением. Исправляй только после согласования объёма, если находишь архитектурную проблему.

Не закрывай release gate без фактических результатов. Итог: список пройденного, непроверенного, дефектов и однозначный статус «готов к техническому MVP / не готов».
