# Журнал продуктовых и архитектурных решений

## Как менять решение

Не переписывать принятое решение молча. Добавить новую запись с датой, причиной, альтернативами, последствиями и списком документов/тестов для обновления. Решения со статусом «Принято» являются обязательными для агентов.

## ADR-001 — Личный локальный MVP

**Статус:** принято.

Одна медсестра, одно Android-устройство, одна активная смена. Без аккаунтов, backend, синхронизации, совместной работы и МИС.

## ADR-002 — .NET MAUI и Android

**Статус:** принято.

C#, .NET 10 LTS, `net10.0-android`, XAML, MVVM. Минимум Android 8.0/API 26 как рабочая рамка; проверить фактический парк до пилота. Preview-версии запрещены.

## ADR-003 — GigaChat как источник черновика

**Статус:** принято.

Прямой REST API, Authorization Key в настройках, фото через file storage и attachments. Модель возвращает JSON 1.0. Обязательное ручное подтверждение всего импорта. Отдельный OCR не включён до исследования качества.

## ADR-004 — Офлайн-планировщик

**Статус:** принято.

После сохранения смена, редактирование, статусы, история и уведомления работают локально. Только GigaChat требует сети. Никакого периодического фонового трафика.

## ADR-005 — Два напоминания

**Статус:** принято.

Предварительное за 10 минут по умолчанию и основное в назначенное время. Интервал 0–60 минут. Неточный fallback молча запрещён. Отказ разрешения виден постоянно.

## ADR-006 — Статусы без автопропуска

**Статус:** принято.

Pending, Done, Skipped. Overdue вычисляется. Пропуск не выставляется автоматически; причина пропуска и полный аудит не входят в MVP.

## ADR-007 — Данные и хранение

**Статус:** принято.

БД шифруется, секреты в SecureStorage, access token в памяти. Фото удаляются после импорта по умолчанию. История — 30 дней по умолчанию с настройками 7/30/90/бессрочно. Cloud backup чувствительных данных отключён.

## ADR-008 — UI

**Статус:** принято.

Нативный спокойный Android UI, три нижних раздела, хронологическая лента, крупное время, системный шрифт, светлая/тёмная тема, доступность AA. Без ИИ-чата, градиентов, эмодзи и декоративных шаблонов.

## ADR-009 — Граница эксплуатации

**Статус:** принято.

Прототип использует только синтетические/обезличенные данные. Реальный пилот требует организационного согласования обработки данных, устройств, установки, поддержки и эксплуатационных инструкций.

## ADR-010 — Реализация локального шифрования

**Статус:** принято 10.11.2026 для технического MVP.

EF Core использует `Microsoft.EntityFrameworkCore.Sqlite.Core` и только `SQLitePCLRaw.bundle_e_sqlcipher` 2.1.11, без одновременного native bundle обычного SQLite. DbContext владеет соединением, создаваемым из connection string. Retained photos шифруются AES-256 со случайным IV; ключ находится в SecureStorage. Миграция и шифрование файла проверены integration-тестами на хосте; Android Keystore/SQLCipher device gate остаётся открытым.

## Открытые технические вопросы, закрываемые spikes

- Конкретная доступная vision-модель GigaChat и измеренное качество.
- Контрольные устройства, Android-проверка SQLCipher/retained photos и фактическое поведение exact alarms/Doze.
- Необходимость настройки цепочки сертификатов на целевых устройствах.
- Инструмент UI automation для MAUI device tests.

Эти вопросы не разрешаются выдуманными фактами в коде или документации.
